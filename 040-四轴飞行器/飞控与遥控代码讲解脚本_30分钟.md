# 飞控 + 遥控 代码讲解脚本（30 分钟 / 按 main 顺序）

> 适用对象：基于 STM32F103 的四轴开源飞控（四轴C程序V2.0 激光）+ 匿名遥控手柄（Remoter_Ctrl3.6）
> 讲解主线：**飞控 main → 遥控 main → 双向通信桥接**
> 核心理念：**两份程序是同一个“时间片轮询”框架的两半**——先建立这个心智模型，后面的所有 `Duty_*` / `ANO_Loop_*` 都挂在它上面。

## 0. 总览（2 min）—— 先讲“框架”，再讲“细节”

**一句话定位**：飞控 = 飞机上的被控端；遥控 = 手里的控制端。两者都是 STM32F103，都长这样：

```
main()
  ├─ 时钟 / SysTick / 中断分组 配置
  ├─ ALL_Init()  （或遥控器里的各 Init）—— 把所有外设打开
  └─ while(1) {
        主循环轮询();   // 飞控: main_loop()，遥控: 仅 Show_Duty() 刷屏
        喂狗();         // 飞控有 IWDG，遥控无
    }
```

**关键心智模型——时间片轮询**：
- `SysTick` 中断每 1ms（遥控 2ms）进一次，在 `Loop_check()` 里把若干计数器 `cnt_2ms / cnt_4ms / …` 各 +1；
- 主循环 `main_loop()` 检查“某个计数器累加到阈值就跑对应档任务”，例如 `cnt_2ms>=1` 跑 2ms 任务，`cnt_4ms>=2` 跑 4ms 任务；
- 这样**所有业务逻辑都挂在 `Duty_Xms` / `ANO_Loop_XHz` 里**，不阻塞、不 delay 死等。

> 讲解提示：这页用一张图讲清“1ms tick → 各档计数器叠加 → 主循环分发”，后面所有函数都“挂”在这张图上。

## 1. 飞控 `main()` 与 `ALL_Init()`（4.5 min）

### 1.1 `main()` —— `USER/main.c:34`
调用顺序：
1. `cycleCounterInit()` —— 启用 DWT 周期计数器，给 `GetSysTime_us()` 提供 us 级时基（后面测各 Duty 耗时用）；
2. `NVIC_PriorityGroupConfig(NVIC_PriorityGroup_4)` —— 4 位抢占优先级；
3. `SysTick_Config(SystemCoreClock / 1000)` —— 1ms 系统滴答；
4. `ALL_Init()` —— 全部外设初始化（**下钻重点**）；
5. `IWDG_Init(4, 625)` —— 独立看门狗，溢出 1s，程序跑飞时复位；
6. `while(1){ main_loop(); IWDG_Feed(); }` —— 喂狗 + 主循环。

### 1.2 `ALL_Init()` —— `USER/INIT.c:59`（3 min 重点）
按初始化顺序逐个点名（强调“先开总线时钟/接口，再初始化设备”）：

| 顺序 | 函数 | 作用 |
|---|---|---|
| 1 | `IIC_Init()` | I2C 总线（MPU6050/磁力计） |
| 2 | `pid_param_Init()` | 全部 PID 参数初值（`INIT.c:110`） |
| 3 | `LEDInit()` | LED 闪灯（含 `GPIO_Remap_SWJ_JTAGDisable` 重映射：禁 JTAG 留 SWD） |
| 4 | `MpuInit()` | MPU6050 |
| 5 | `ADC1_Init()` | 电压采样 |
| 6 | `ANO_Uart1_Init(19200)` | **USART1 接光流模块** |
| 7 | `UART2_Init(115200)` | 仅 `FLY_TYPE==2` 才开（预留视觉口，空置） |
| 8 | `USART3_Config(500000)` | **USART3 接匿名上位机** |
| 9 | `NRF24L01_init()` | 2.4G 遥控通信（SPI） |
| 10 | `spl0601_init()` | 气压计；**失败有 break，置 `SPL_Err`，不死循环** |
| 11 | `TIM2_PWM_Config()` / `TIM3_PWM_Config()` | 4 路电机 PWM |

⚠️ **可提一句风险**（来自运行检测报告 P1）：`MpuInit()` / `NRF24L01_init()` 内部是 `do{…}while(==FAILED)`，**若硬件没焊好会死循环卡死**，讲初始化时可顺带点出“工程健壮性隐患”。

## 2. 飞控时间片调度器（1.5 min）—— `USER/scheduler.c`

- `Loop_check()`（`scheduler.c:13`）：SysTick 中断里调用，6 个计数器 +1，并置 `check_flag`；
- `main_loop()`（`scheduler.c:32`）：按阈值分发：
  - `cnt_2ms>=1` → `Duty_2ms()`
  - `cnt_4ms>=2` → `Duty_4ms()`
  - `cnt_6ms>=3` → `Duty_6ms()`
  - `cnt_10ms>=5` → `Duty_10ms()`
  - `cnt_20ms>=10` → `Duty_20ms()`
  - `cnt_50ms>=25` → `Duty_50ms()`
  - `cnt_1000ms>=500` → `Duty_1000ms()`
- 结尾 `loop.check_flag = 0`，完成一轮。

> 讲解提示：把第 0 段的图接上，标出每个 `Duty` 的频率，告诉听众“接下来 3 分钟逐个进 2ms 任务，再进 6ms…”。

## 3. 飞控 `Duty_2ms()` —— 控制闭环（4.5 min）★ 全场最重要

`USER/scheduler.c:77`：
```
MpuGetData();                // 读传感器
FlightPidControl(0.002f);    // 姿态控制
MotorControl();              // 电机控制
```

**3.1 `MpuGetData()`（`HARDWARE/mpu6050.c`，约 110 行）**
- `Acc_Read()` / `Gyro_Read()` 读原始值；
- 减 `MpuOffset[i]` 零偏；
- 加速度计：一维卡尔曼滤波 `kalman_1()`；陀螺仪：一阶低通 `0.15f` 系数；
- 产出 MPU6050 原始数据，供 6ms 解算与 2ms 内环使用。

**3.2 `FlightPidControl(0.002f)`（`HAL/control.c`）**
- 状态机 `PROCESS_xx`：上电 → 等待 → 解锁 → **`PROCESS_31` 正式进入控制**；
- **姿态串级 PID**：外环角度（`pidRoll/pidPitch/pidYaw`，输入 `Angle`）× 内环角速度（`pidRateX/Y/Z`，输入陀螺仪）级联；
- 输出姿态控制量。

**3.3 `MotorControl()`（`HAL/control.c`）**
- 把姿态 PID 输出 + 油门，按 **X 型四轴**映射到 4 路电机 PWM。

> 讲解提示：用一张“控制闭环图”串起：`MPU6050 → MpuGetData → (6ms) GetAngle → .measured → FlightPidControl → MotorControl → 电机`。
> ⚠️ 顺带点出已知 bug（检测报告 P0）：**偏航级联 `pidRateZ.desired` 未被赋值、外环 `pidYaw.out` 被丢弃 → 航向失控**，是飞行层面最大阻断点。

## 4. 飞控 `Duty_6ms()` —— 姿态解算（2 min）

`USER/scheduler.c:99`：
```
GetAngle(&MPU6050, &Angle, 0.006f);   // MATH/imu.c
```
- 四元数/互补融合，输出 `Angle.roll / Angle.pitch / Angle.yaw`；
- **衔接关系**：解算结果喂给 2ms 姿态 PID 的 `.measured`（反馈量）。
> 讲解提示：强调“采样在 2ms、解算在 6ms、控制在 2ms”的错位并行设计，是实时系统的典型手法。

## 5. 飞控 `Duty_4ms()` —— 通信与解锁（3 min）

`USER/scheduler.c:88`：
```
ANO_NRF_Check_Event();     // 收 2.4G 遥控数据
ANO_DT_Data_Exchange();    // 回传飞机数据到遥控
Rc_Connect();              // 解析通道 / 连接检测
Mode_Controler(0.004f);    // 模式选择 + 解锁判断
```
- `ANO_NRF_Check_Event()`：NRF 中断收包，把遥控通道搬进解析缓冲；
- `ANO_DT_Data_Exchange()`（`HAL/ANO_Data_Transfer.c`）：打包 `0xAA 0xAA 0x01`(姿态) / `0x05`(电压) 回传遥控；
- `Rc_Connect()`：解析通道值；**成功分支为空 `{}`**（已知软性预留，见报告）；
- `Mode_Controler()`：飞行模式 + 解锁逻辑。
> 讲解提示：本段是“飞控接收端”，与第 11 段遥控发送端、第 13 段桥接呼应。

```
RC_Analy();                 // 遥控指令处理（含失联保护）
```

> 讲解提示：这些是“进阶稳定功能”，基础自稳靠第 3/4 段；可说明“光流/高度是叠加在姿态环之上的外层”。

## 8. 遥控 `main()` 与初始化（1.5 min）—— `ANO_Remoter/main.c:22`

调用顺序（与飞控对照讲）：
```
RCC_Configuration();        // 开时钟(USART1/SPI1/ADC1/TIM3/USART3/I2C1)
NVIC_PriorityGroupConfig(4);
ANO_LED_Init();             // LED + 蜂鸣器
ANO_Param_READ();           // 从 Flash 读参数
USB_HID_Init();             // 接匿名上位机(地面站)
ANO_SPI_Init();             // NRF 用的 SPI
NRF_ENABLE = ANO_NRF_Check(); // 检测 NRF 是否在位
if(NRF_ENABLE) ANO_NRF_Init(MODEL_TX2, ch);  // 设为主发送
ADC1_Init(); KEY_Init(); OLED_Init();
SysTick_Config(CoreClock/500);   // 2ms 中断
while(1) if(Show.oled_delay) Show_Duty();  // 主循环只刷屏！
```
> 讲解提示：**遥控的“真正逻辑”不在 `while(1)`，而在 SysTick 中断触发的 `ANO_Loop` 调度器里**（代码注释连写三遍“全部运行程序在 ANO_Scheduler.c”），这点要和飞控的 `main_loop`（主循环里跑）对比，是两者框架的细微差异。

## 10. 遥控 `ANO_Loop_500Hz`（2ms）—— 摇杆采集（2.5 min）★ 重点

`ANO_Scheduler.c:18`：
```
ANO_NRF_Check_Event();   // 顺便收飞机回传
ANO_Stick_Scan();        // 读遥杆
```
**`ANO_Stick_Scan()`（`ANO_Stick.c:128`）逐层讲**（这是遥控“输入”的全部）：
1. `ADC_ConvertedValue[x]` → 比例换算 `1000 + 0.25*ADC` → 减 `ANO_Param.OffSet_*`（中点偏置）；
2. `American_Mode` 摇杆映射：THR/PIT/YAW/ROL 与 4 路 ADC 通道的对应关系（注意 THR 与 PIT 的通道互换）；
3. `Window_Filter()` —— 滑动窗口滤波（丢旧值、加新值、求平均）；
4. `Mid_Offset()` —— 摇杆中点校准，结果存 Flash（`ANO_Param_SAVE()`）；
5. `RC_Limit()` —— 1000~2000 限幅；
6. `Mid_Limit()` —— ±10 死区归中。
> 讲解提示：本函数是“人手 → 数字量”的入口，讲清“滤波+校准+限幅”三件套，遥控的精华就在这。

## 11. 遥控 `ANO_Loop_250Hz`（4ms）—— 发送控制（1.5 min）

`ANO_Scheduler.c:30`：
```
if(USB_ReceiveFlg) ANO_NRF_TxPacket(Hid_RxData, len); // 上位机透传
```

- `ANO_DT_Send_Data()` → `ANO_NRF_TxPacket()` 发往飞机。
> 讲解提示：这就是“遥控发往飞控”的那一帧，与第 5 段飞控 `ANO_NRF_Check_Event` 收包、第 13 段桥接直接对应。

## 12. 遥控其余档（0.5 min，简述）

- `100Hz`：`key_function()` / `Gesture_Check()` 菜单操作；
- `50Hz`：`ANO_key()` 按键扫描；
- `20Hz`：`Show.oled_delay=1`（触发 `main` 里刷屏）+ `NRF_Check_Ch()` 自动对频；
- `1Hz`：电池电压检测、`NRF_SSI` 帧率统计、**`NRF_SSI==0 → Connect_Succeed=0` 失联判定**。
> 一句话带过：慢速任务，与飞控 20/50/1000ms 档对应。

## 13. 飞控 ↔ 遥控 通信桥接（2.5 min）—— 把两边“合体”

**下发（手柄 → 飞机）**：
```
遥控 ANO_DT_Send_RCData()  (0xAA 0xAF 0x03, 通道值)
   → ANO_NRF_TxPacket()
   → 飞控 ANO_NRF_Check_Event() 收包
   → Rc_Connect() / RC_Analy() 解析为 Remote
```

**回传（飞机 → 手柄）**：
```
飞控 ANO_DT_Data_Exchange()  (0xAA 0xAA 0x01 姿态 / 0x05 电压)
   → NRF 发
   → 遥控 ANO_NRF_Check_Event() 收
   → ANO_DT_NrfData_Anl() 解析 (ANO_DT.c:98)
   → OLED 显示 Show.X/Y/Z/H、电压、模式
```

**帧格式对照**：
| 方向 | 帧头 | 功能字 | 内容 |
|---|---|---|---|
| 遥控→飞控 | `AA AF` | `03` | THR/YAW/ROL/PIT/AUX |
| 飞控→遥控 | `AA AA` | `01` | 姿态角 roll/pitch/yaw + 高度 |
| 飞控→遥控 | `AA AA` | `05` | 电压/硬件类型/传感器状态/模式 |

> 讲解提示：这是“飞控+遥控一起讲”的精华——两边是同一套匿名协议的两个端点。讲完这页，听众就建立了“一个手柄、一架飞机、一根 2.4G 无线、一套协议”的完整画面。

## 14. 收尾 + 已知问题提示（1.5 min）

**已知遗留（来自《飞控代码运行检测报告》，可按需展开）**：
- 🔴 P0 偏航级联断开：`pidRateZ.desired` 未赋值、`pidYaw.out` 丢弃 → 航向失控；
- 🟠 P1 初始化 `do…while(FAILED)` 死循环风险（MPU/NRF 焊坏即卡死）；
- 🟠 P1 WiFi 遥控失效：`Uart1.c` 解析被注释 + `WIFI_UFO.c` 一键动作只置标志不执行；
- ⚠️ 命名误导但逻辑正确：`RC_Analy` 的 `Nrf_Erro==1` 实为“有信号”，非“写反”。

**互动预留**：可在此抛问题——“如果让你补全偏航控制，你会改 `control.c` 哪几行？”引导思考。
