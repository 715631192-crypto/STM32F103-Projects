③ buzzer_process() 每 10ms 的步进逻辑
void buzzer_process(void) // 10ms 调用一次 { if (s_pattern == 0) return; // 空闲：无模式在播 dur = s_pattern[s_idx]; // 取当前拍时长(×10ms) if (dur == -1) { // 上一拍播完，本次收尾 BUZZER_OFF(); s_pattern = 0; // 关响 + 清模式 return; } if ((millis()-s_tlast) >= dur*10) { // 当前拍到点？ s_tlast = millis(); // 记录切换时刻 s_idx++; // 进下一拍 if (s_pattern[s_idx] == -1) // 下拍是结束符 BUZZER_OFF(); // → 关响（下周期清表） else if (s_idx % 2) // 奇数拍 BUZZER_ON(); // → 响 else // 偶数拍 BUZZER_OFF(); // → 停 } }
设计要点
▸ 非阻塞：只用 3 个状态变量（模式指针 / 节拍索引 / 切换时刻），无阻塞等待，10ms 一拍与 RGB 同节拍。
▸ 时间基准：(millis()-s_tlast) 无符号减法，自动容忍 millis() 回绕。
▸ “停”拍无需反复写：电平只在到点时翻转一次，停拍期间保持上次 OFF 状态（beep 入口已先关一次）。
▸ 触发即重播：buzzer_beep() 直接换表并复位，连续按键时每次按键都从头播，天然支持“抢拍”。
▸ 结束收尾分两拍：s_idx++ 后遇 -1 只先关响，下一个 10ms 的 “dur==-1” 分支才清 s_pattern=0 —— 功能无影响。
▸ LOCKOUT 预留：pat_lockout 已定义，但当前应用层锁定（LOCK_STATE_LOCKOUT）走的是 board_auth_feedback(false)→BEEP_ERR，四短音尚未接线。
