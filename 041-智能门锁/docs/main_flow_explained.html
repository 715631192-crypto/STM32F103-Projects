STM32 智能门锁固件 · main() 执行流程讲解

按 main() → smart_lock_app_start() → board_init() → 队列/任务创建 → vTaskStartScheduler() 的真实调用顺序梳理。代码位置：firmware/stm32/src/main.c、board_port.c、smart_lock_app.c。

一句话总览：main() 只做两件事——调用 smart_lock_app_start() 把硬件、配置、队列、任务全部准备好，然后 vTaskStartScheduler() 把 CPU 交给 FreeRTOS。之后 main() 永不返回，所有工作由 5 个并发任务完成。

2. board_init() 内部 9 步初始化顺序

位于 board_port.c:610。顺序很关键：先释放 JTAG 脚才能用键盘；先 IIC_Init 才能 OLED_Init；先 W25Q64_Init 成功才继续；RC522 首次初始化可能失败需重试。

3. FreeRTOS 5 任务运行时与队列关系

vTaskStartScheduler() 之后，5 个任务并发跑。它们不直接互相调用，而是通过队列解耦：输入/网络把事件塞进队列，access 消费并决策，ui/log 负责呈现与落盘。

4. 逐段代码讲解

4.1 main() — 入口极简（main.c:17-34）

int main(void){
    if (!smart_lock_app_start()) {
        for (;;) {}            // 启动失败：死循环等看门狗
    }
    vTaskStartScheduler();    // 交出 CPU，永不返回
    for (;;) {}               // 仅堆不足导致调度器没起来才会到这
}

main() 只做两件事：① 调 smart_lock_app_start() 完成一切准备工作；② 调 vTaskStartScheduler()。72MHz 时钟由启动文件里的 SystemInit() 配好，main 不再碰时钟。若准备失败（Flash 无响应/配置写不进/任务创建失败）就原地死循环，由看门狗复位；正常路径 main() 不会走到最后一行。

4.2 smart_lock_app_start() — 准备阶段（smart_lock_app.c:1808-1877）

这是真正干活的"总装车间"，按顺序做四组事：

  • 硬件board_init()：见 4.3，把 9 类外设全部初始化。
  • 配置board_security_load() 从 W25Q64 读出厂/已存的安全配置（主密码、胁迫密码、TOTP 种子等），再 security_config_valid() 校验信封（版本+序号+CRC32）。
  • 日志event_log_init() 挂上 W25Q64 的读写擦回调，准备好环形审计日志。
  • 内核对象清状态变量 → lock_controller_init()（自动落锁延时）→ set_physical_state() 让舵机实际锁门。然后 xQueueCreateStatic() 创建 6 个队列：input / remote / log / notify / ui / log_request，全部静态分配（工程堆仅 4KB）。最后 xTaskCreateStatic() 创建 5 个任务，任何一步失败都返回 false。

全部成功后 queue_ui(controller.state, "System ready", true) 让屏幕显示就绪，返回 true 给 main。

4.3 board_init() — 9 步硬件初始化（board_port.c:610-729）

顺序见流程图 2，要点：

步做了什么为什么这个顺序
1sys_init() NVIC 分组 + 释放 PA15/PB3/PB4不释放 JTAG 脚，键盘行就不可用
2USART1/2/3 初始化先有调试串口，后面才有 printf 输出
3IIC→OLED→Clear / 蜂鸣器 / RGB必须先 IIC_Init 才能驱动 OLED；OLED_Clear 清掉上电随机显存，避免"乱屏"
4W25Q64 存储失败直接 return false，因为配置和日志都依赖它
5RC522 读卡上电瞬间芯片状态机没起来，Check 不通就再 Init 一次救回
6DS3231 时钟读 UTC 并打印，无 ACK 自动回落软时钟
7舵机 servo_init + servo_lock上电即锁门，安全优先
8键盘 + 唤醒键初始化扫描状态结构体
9app_wifi_init + watchdog_init注册 MQTT 下行回调、开看门狗，最后打印 [BOOT] ready

4.4 vTaskStartScheduler() — 进入多任务（main.c:29）

调度器启动后，5 个任务按优先级被调度。FreeRTOS 用全静态分配（无动态堆申请），所以启动几乎不会因内存失败。此后 main() 不再执行，CPU 在任务间切换。

4.5 五个任务的"死循环"（smart_lock_app.c）

任务优先级节拍职责
input_task310msboard_poll_input() 扫键盘，事件塞进 input_queue
access_task4（最高）100ms消费 input/remote 队列 → 鉴权决策 → 锁控；管理菜单；每秒 tick 处理自动落锁/门未关/进 STOP 省电
network_task250ms轮询 ESP8266 收远程指令塞 remote_queue；发 notify_queue 里的上报
log_task150ms消费 log_queue 写 W25Q64 审计日志；响应 log_request_queue 回读
ui_task1阻塞等等 ui_queue，调 board_ui_show()/board_menu_show() 刷屏

优先级数字越大越高：access(4) > input(3) > network(2) > log/ui(1)。access 最高是因为开锁决策必须及时；ui 最低，刷屏慢一点不影响安全。各任务通过队列解耦，互不直接调用——这也是为什么 I2C 总线要加"事务层递归锁"（见长记忆第八节）：OLED 与 DS3231 共用 PB8/PB9，被不同优先级任务访问时若不锁住整笔事务就会屏幕错乱。
